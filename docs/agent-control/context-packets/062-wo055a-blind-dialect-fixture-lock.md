# WO-055A Blind All-Language Dialect Fixture Lock

## Objective

Select and freeze one fresh, real, immutable task for each of Cortex's 14
programming-language families, prove that every selected unchanged source scope
contains at least two genuinely comparable implementation owners, build the
clean non-dialect index bindings, and initialize the accepted six-phase dialect
evaluation run lock.

This work order freezes inputs only. It must not author gold facets, inspect or
run the experimental recurrence output, freeze baseline/candidate treatment
output, score any claim, reveal a patch, change production code, or decide the
all-language hypothesis.

## Why WO-055 Is Split

WO-055 contains four trust-separated steps that cannot safely share a long
session:

1. WO-055A freezes fresh tasks, base trees, source catalogs, clean indexes,
   retrieval budget, and the run lock.
2. WO-055B is a blind gold session that receives unchanged code/scopes but no
   task text, patch, treatment output, or candidate observations.
3. WO-055C receives the private task bytes and freezes baseline then candidate
   outputs without gold or scoring access.
4. WO-055D scores immutable artifacts before any optional reveal, performs the
   second clean replay, and obtains independent final review.

Failure at any step is a valid result and blocks the later steps. Gates may not
be lowered and failed tasks may not be silently replaced after output is seen.

## Fresh Task Contract

Freeze exactly 14 task bindings: one for each manifest family
`javascript`, `typescript`, `c`, `cpp`, `rust`, `python`, `go`, `java`, `ruby`,
`bash`, `csharp`, `vbnet`, `vb6`, and `sql`.

Every task must:

- be a concrete maintenance/change request grounded in a real repository at an
  immutable 40-64 hex base commit and root tree;
- use exact UTF-8 task bytes within the accepted `max_task_bytes` bound;
- have a unique visible task ID, exact byte count, and SHA-256;
- bind a non-empty, sorted canonical repository-relative source scope;
- have at least two unchanged regular source files or chunks in that scope that
  are genuinely comparable implementation owners;
- use only parser modes belonging to its frozen family;
- be absent by task ID, task hash, issue identity, base/patch tuple, and known
  prior task aliases from WO-D, WO-043 through WO-050, AgentStackBench result
  fixtures, and every existing dialect result or fixture;
- be chosen before any gold, candidate recurrence output, candidate claim,
  patch, or post-change source is inspected.

Task selection may inspect unchanged source, tests, repository metadata, and
issue text. It may not inspect a solution patch or use gold/mechanism rubrics to
optimize selection. If a family has no valid fresh task, record NO-GO for
availability; do not substitute a synthetic parser fixture or lower the gate.

## Private Task-Byte Separation

The tracked fixture contains task bindings and hashes, never task text. Exact
task bytes are written atomically to one outside-Git private bundle with mode
`0600`. Its absolute location is recorded only in the manager return, while the
tracked attestation records its byte length and SHA-256, not its contents.

- WO-055B must not receive or read the private bundle.
- WO-055C may receive the exact private bundle as a direct reference.
- Task text is never copied into the accepted evaluation run artifacts.
- A missing, wrong-mode, symlinked, hard-linked, oversized, or hash-mismatched
  private bundle is fatal and cannot be reconstructed from memory.

The private bundle must survive until WO-055 is accepted or rejected. No task
text may appear in logs, diagnostics, tracked fixtures, the report, or chat
summaries.

## Frozen Fixture and Attestation

The tracked fixture is a closed canonical JSON object containing:

- schema/artifact identity and frozen timestamp;
- all accepted runtime contract/capability/limits hashes;
- exactly 14 sorted public task bindings;
- repository URL/key, base commit, root tree, source scope, and family per task;
- exact source catalogs with path, SHA-256, byte count, and line count;
- source-tree, non-dialect-index, retrieval-budget, and fixture-set hashes;
- comparable-owner availability counts and content-derived owner/location IDs,
  but no inferred dialect statement or gold facet;
- clean-workspace and parser-availability facts;
- a closed contamination audit listing every searched prior authority and zero
  collisions;
- the validated `createDialectEvaluationRunLock` output.

The detached attestation binds the fixture file hash, report file hash, private
bundle hash/bytes/mode, generator hash, and every external repository/base-tree
identity. A file cannot truthfully contain its own byte hash, so file hashes
belong only in the detached attestation.

## Clean Index and Baseline Isolation

For each task, build from a clean detached checkout at the exact base commit.
Use the accepted bootstrap/index path and the task's frozen source scope.

- Derive `non_dialect_index_sha256` only from the accepted legacy documents,
  chunks, relations, graph inputs, embeddings metadata/content, conventions,
  and guidance inputs selected by the run-lock contract.
- The dialect sidecar and its additive manifest field are excluded from this
  hash and must not influence selection.
- Freeze one canonical retrieval budget for all treatments. The candidate path
  remains one `top_k: 50` lexical/graph-only call with `query_vector: null`;
  baseline and candidate receive the same task/base/scope and non-dialect
  inputs.
- Do not invoke `runDialectPatternEvidence`, inspect persisted observations, or
  render candidate output in WO-055A.
- Network access is allowed only to fetch the named public repositories and
  immutable base objects. No model, provider, planner, telemetry, solution
  agent, or arbitrary service call is authorized.

## Required Negative Behavior

The generator and tests fail closed on:

- missing/duplicate family or task, unknown family/mode, reordered closed data,
  task-byte/hash mismatch, non-canonical scope/path, or invalid base identity;
- dirty checkout, missing base object, root-tree drift, source-catalog drift,
  symlink/hard-link/special source, or source outside the frozen scope;
- fewer than two comparable owners, one owner with two spans, duplicate
  owner/span evidence, or owner/location data derived from candidate output;
- any prior-task collision or incomplete contamination authority;
- private bundle path/mode/type/link/hash/size failure;
- index/hash/retrieval-budget drift or a non-zero model/provider/planner/
  telemetry/solution-call counter;
- any attempted gold, treatment, score, reveal, production, package, or public
  API mutation.
